They differ in exactly one attribute: `capture="environment"` sends iOS straight to the camera, and without it the same control offers the photo library. That is the whole difference, and it is invisible to any test we can write — worth checking on a real phone when this changes. Sharing the name is safe because Django's MultiPartParser skips file parts with no filename, so the untouched input contributes nothing and `request.FILES.get("receipt")` finds the one that was used. It also keeps the submit button below a valid fallback for either path, for anything that does not run the onchange. Neither input is `required` any more: with two of them, exactly one is filled on any given submission, and marking both required makes the form unsubmittable. The view already answers an empty submission with "Choose a photo of your receipt." {% endcomment %}
